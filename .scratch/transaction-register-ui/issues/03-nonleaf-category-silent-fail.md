# Category selector allows non-leaf categories, then Save silently fails

Status: resolved
Category: bug
Severity: medium
Area: Transaction register

The Category selector allows selecting a non-leaf category without any warning. When you press
Save, nothing happens — as if the button is broken — but the logs show an error about a
non-leaf account.

The Category selector should not allow selecting non-leaf categories, or at least make the user
aware of the problem instead of failing silently.

## Agent Brief

**Category:** bug (with an enhancement rider — the composed hierarchy labels)
**Summary:** Non-leaf categories are offered and accepted by the Category picker, failing only at
commit; stop offering/accepting them, and display the offered categories as composed `Parent -
Child` paths so the hierarchy is legible.

**Current behavior:**
The dock's Category field and the split panel's per-line Category field are both native
`<input list=…>` datalists fed by one source — the register view's category options — and both
resolve through the shared `/categories/resolve` endpoint. That option list offers *every* live
income/expense account except the auto-managed per-currency leaves, so **semantic parents** (a
category that has real, non-currency-leaf children) appear as selectable options, shown by their
bare name (`Milk`, not `Food - Milk`). The name-based resolver matches a parent by name and returns
its account id with no error. The failure only surfaces at commit, where the double-entry engine
rejects a posting to a non-leaf account. Since the issue-05/10 error-boundary work, that rejection
is now shown as a dock error rather than a dead button — but the user is still never warned at
selection time, and a non-leaf is still fully selectable and resolvable.

Important subtlety: "non-leaf" here means **has at least one real (non-currency-leaf) child**. A
category whose only children are the auto-managed per-currency leaves (`Food-EUR`, `Food-CHF`) is
still a valid posting target — routing to the currency leaf is automatic. The guard must count only
non-currency-leaf children (the same `parentHasRealChildren` notion the category-creation logic
already uses).

**Desired behavior:**
1. The Category datalist offers only genuinely-postable categories (leaves in the semantic sense
   above). Semantic parents are excluded from the offered options.
2. Offered categories are labelled by their full path using the existing ` - ` create separator, so
   an existing leaf under `Food` shows as `Food - Milk`. This is the *same string* the field
   already accepts to create a new leaf (`Parent - Child`), so display, selection, and creation all
   speak one syntax. Top-level leaves keep their bare name.
3. The resolver, given a full-path string, matches an existing leaf by that path **before** falling
   through to its create-a-new-`Parent - Child` behavior — so picking `Food - Milk` for an existing
   `Milk` resolves to that leaf rather than trying to create a duplicate/subdivide.
4. If a non-leaf category is nonetheless submitted (e.g. the user types a parent's name directly),
   the resolver refuses it with a clear inline error in the category-resolved fragment — the same
   way an unknown/ambiguous category is already refused — so nothing can carry a non-leaf id to
   commit. No silent path to a commit-time failure remains.

**Key interfaces:**
- The register view's category-option projection (a `RegisterCategoryOption`-style record carrying
  `accountId` + display name, produced by the register service's `categoryOptions()`): exclude
  semantic non-leaves, and emit the composed `Parent - Child` full-path name. Compose the path
  root-to-leaf over the hierarchy — mirror the existing tag full-label composition
  (`TagReadRepository` builds `Parent:Child` labels the same way), and the depth-annotated
  `findLiveByTypesWithDepth` / `AccountNode` already used to render the categories screen tree.
- `CategoryService.resolveCategory(String)`: add a full-path exact match against composed leaf paths
  ahead of the current bare-name match and the `Parent - Child` create fallback; and make it reject
  a resolved account that is a non-leaf (has a real child) with an `IllegalArgumentException`, which
  the `/categories/resolve` handler already renders as an inline error with no committable id.
- Both the dock (`entry-category-options` / `categoryId`) and the split panel
  (`split-category-options` / `lineCategoryId`) inherit the fix through the shared option source and
  shared resolver — no per-surface duplication.

**Acceptance criteria:**
- [ ] The Category datalist (dock and split panel) lists only postable leaf categories; a parent
      with a real child does not appear as an option.
- [ ] An offered category under a parent is shown as `Parent - Child`; a top-level leaf shows bare.
- [ ] Selecting an offered `Parent - Child` for an existing leaf resolves to that leaf's id (no new
      account created, no subdivision triggered).
- [ ] Typing an existing parent category's name resolves to an inline error and leaves the hidden
      category id empty, so Save is not possible with a non-leaf selected.
- [ ] Creating a genuinely new leaf via `Parent - Child` still works (unchanged).
- [ ] Transfer targets (`To → …` / `From ← …`) and person targets (`for …` / `by …`) are unchanged.
- [ ] A category whose only children are auto-managed per-currency leaves is still offered and still
      commits correctly (it is a valid posting target).
- [ ] `./gradlew check` is green (new/updated tests in the right tier: resolver path-matching &
      non-leaf rejection are decision logic; any new full-path composition query is SQL-resident →
      `sqlLogicTest`).

**Out of scope:**
- Replacing the native datalist with a `<select>` or any custom dropdown widget (would lose
  free-text create and the `To →`/`for` sigils, and adds app-wide JS — rejected during triage).
- True visual indentation (native datalists cannot be styled; the composed path label is the agreed
  substitute).
- The other open register-UI issues (01, 02, 04, 06, 07, 08).

## Resolution

> *This was generated by AI during triage.*

Fixed in `99dcf82` (branch `fix/category-nonleaf-selector`). The Category datalist
(dock + split panel) now offers only genuine posting leaves, each labelled by its full
`Parent - Child` path (native datalists can't indent). A non-leaf group is refused at
resolve time with an inline error and no committable id, so there is no silent path to a
commit-time failure. A leaf whose only children are auto-managed per-currency leaves stays
postable. `./gradlew check` green; owner-confirmed (tested 2026-07-21).
