# Create/delete logging for people, accounts, categories, and receipts

Status: resolved
Category: enhancement
Severity: high
Area: Cross-cutting — `accounts`, `categories`, `debts`, `receipts` service layers

## Request (owner)

Log every creation and deletion of a person, account, or category — INFO level, id and name only.
Same for a receipt upload/delete, with id, file size, and path. It's specifically useful to see the
*causal chain*: e.g. a new person being created and, right after, the account being opened for
them — that tells the story of what happened and why, so both events should log, not just one
merged line.

## What exists today

None of these call sites log anything on success today.

## Agent Brief

**Category:** enhancement

**Summary:** Add INFO-level logging at every service-layer call site where a person, account,
category, or receipt is created or (soft-)deleted — including automatic/internal provisioning
paths, not just the explicit Create screens — so cascading/automatic creation (e.g. a person's leaf
account, a category's auto-provisioned currency leaf) tells a readable causal story in the logs.

**Desired behavior — the two-level pattern (owner-agreed):** each entity's own module logs its own
"why" event, and `AccountService` *additionally* logs its own generic "Account opened"/"Account
soft-deleted" event for every account row it touches, regardless of which module called it. Two
lines for a person's first transaction ("Person created" then "Account opened") is intentional, not
duplication — it's the causal chain the owner wants visible.

Content for every line: **id and name only** (receipts: id, file size, path) — no balances, no
other fields.

Call sites (verified in the code):

- **`accounts.AccountService`** — `openAccount` (real account), `insertLeaf` (generic leaf — used
  by category creation, subdivision, currency provisioning), `insertCurrencyLeaf` (auto-provisioned
  per-currency leaf), `insertPersonLeaf` (person's debt leaf) each log INFO
  `"Account opened: id={}, name={}"` on success. `softDelete(List<Long> accountIds)` logs one INFO
  `"Account soft-deleted: id={}, name={}"` line **per account id** in the list (fetch the name
  before the bulk update if the repository doesn't already return it) — mirrors the per-account
  creation lines for a cascading category delete.
- **`categories.CategoryService`** — `createCategory` logs INFO
  `"Category created: id={}, name={}"` after `accountService.insertLeaf(...)` returns (that call
  already logs its own "Account opened" line — this is the *why*). `deleteCategory` logs INFO
  `"Category deleted: id={}, name={}"` for the subtree root before delegating to
  `operations.DeletionService.deleteCategory`, which triggers the per-account "Account
  soft-deleted" lines for the whole subtree via `accountService.softDelete`.
- **`operations.SubdivisionService`** — the child + catch-all it creates via
  `accountService.insertLeaf` are already covered by that call's own "Account opened" line; add
  whatever "why" line reads naturally for this class (e.g.
  `"Category subdivided: id={}, into={}"`) — exact wording is an implementation call.
- **`operations.CurrencyLeafService` / `CurrencyProvisioningService`** — same treatment: their
  calls into `accountService.insertCurrencyLeaf`/`insertLeaf` are covered by that method's own log;
  add a "why" line in whichever of these two classes decides "this category needs a new currency
  leaf" (e.g. `"Category currency leaf provisioned: id={}, category={}, currency={}"`).
- **`debts.PersonService`** — `create` logs INFO `"Person created: id={}, name={}"`;
  `softDeleteIfZeroBalance` logs INFO `"Person deleted: id={}, name={}"`.
- **`debts.PersonProvisioningService`** — the auto-provisioning path (first `for`/`by` reference to
  a brand-new name) also logs "Person created" the same way — a person genuinely comes into
  existence here too, not just via the explicit People-page Create form; its `insertPersonLeaf`
  call gets its own "Account opened" line for free.
- **`receipts.ReceiptService`** — `capture` logs INFO
  `"Receipt uploaded: id={}, size={} bytes, path={}"` after `receiptStorage.storeOriginal` returns;
  `delete` and `deleteSelection` log INFO `"Receipt deleted: id={}"` (one line per id for
  `deleteSelection`, matching the per-account pattern for cascades) — note whether files were
  removed too, since that's a real fork in behavior (the `removeFiles` param).

**Key interfaces:** the classes/methods named above. Add a `Logger LOG` field to any that lack one
(`CategoryService`, `PersonService`, `PersonProvisioningService`, `SubdivisionService`,
`CurrencyLeafService`, `CurrencyProvisioningService`, `ReceiptService` — check each at
implementation time; `AccountService` needs one too unless it already has one from other work).

**Acceptance criteria:**
- [ ] Creating a person from the People page logs "Person created" then "Account opened" (if the
      leaf provisions at creation time — if it's lazy until first transaction instead, the second
      line appears then, which is still correct).
- [ ] Entering a transaction with a brand-new `for`/`by` name logs "Person created" then "Account
      opened" for the auto-provisioned leaf.
- [ ] Creating a category from the categories screen logs "Category created" then "Account opened".
- [ ] Subdividing a category logs an "Account opened" line for each new child/catch-all account,
      plus the subdivision-level "why" line.
- [ ] Spending in a new currency under an existing category logs an "Account opened" line for the
      auto-provisioned currency leaf, plus the currency-provisioning "why" line.
- [ ] Deleting a category subtree logs "Category deleted" for the root, then one "Account
      soft-deleted" line per account in the subtree.
- [ ] Soft-deleting a zero-balance person logs "Person deleted".
- [ ] Opening a real account from the accounts screen logs "Account opened".
- [ ] Uploading a receipt (mobile or PC) logs "Receipt uploaded" with id, size, and path.
- [ ] Deleting one or more receipts logs "Receipt deleted" per receipt.
- [ ] No line logs anything beyond id/name (or id/size/path for receipts) — no balances, no other
      fields.
- [ ] `./gradlew check` green.
