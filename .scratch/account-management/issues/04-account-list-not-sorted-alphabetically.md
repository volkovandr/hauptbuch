# Account list is in creation order, not alphabetical

Status: resolved
Category: bug
Severity: minor
Area: Account management (account list ordering) — also affects the register's account filter

## The problem

The accounts screen lists accounts in the order they were created, not alphabetically. With 41 own
accounts the list is effectively unordered to read.

The cause is the live-accounts-by-type query's `order by`, which sorts top-level accounts by
`coalesce(parent_id, account_id)` — for a top-level account that is its own id, i.e. **insertion
order**. Children are correctly alphabetical within their parent, so the query's own documentation
("alphabetical within a level") is true for children and false for parents.

The same query backs the **register's account filter**, so that screen inherits the same ordering.
A sibling query already returns the correct order — alphabetical, depth-first, with a depth
annotation — and the categories screen uses it.

## Triage note — where the fix lands

**Do not implement this standalone.** The fix ships as part of **transaction-register-ui/22**, whose
brief lists it as a required deliverable with its own acceptance criterion. That issue replaces the
register's account filter with a picker strip reading the very same query; shipping five new pickers
over a creation-ordered list would carry this bug into a new screen, so the two changes belong in one
diff.

This file exists to record the defect and its cause, and is marked `resolved` when 22 lands.

**Expected behavior:** accounts are ordered alphabetically, parents before their children, and
alphabetical among siblings at each depth — on the accounts screen and in the register's account
filter alike.

### Update 2026-09-07 — resolved with transaction-register-ui/22

`AccountRepository.findLiveByTypes` now selects from the shared `LIVE_TREE_CTE` (the same recursive
walk `findLiveByTypesWithDepth` uses), ordered `type, sort_path` — parents before children,
alphabetical among siblings at each depth. The register's account filter reads this and is
alphabetical; the accounts screen was already on the depth query. Ordering cases in
`AccountTreeSqlLogicTest`. Owner-confirmed as part of #22 (branch `feat/register-filter-picker`).
