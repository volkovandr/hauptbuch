# Landing page: pinned account balances

Status: ready-for-agent
Category: enhancement
Severity: low
Area: Landing page (`ledger`), account editor (`accounts`)

The landing page is empty past the "Hello, %name%" greeting. Add an opt-in per-account flag that
surfaces chosen accounts and their balances on the landing page, so opening the app immediately
answers "how much money do I have".

Grilled into shape with the owner 2026-08-28 (see `## Comments`). Split from a combined
landing-page issue; the tracking-stats widget is issue `02`.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Add an account-level "show on the main page" flag; render the flagged accounts and their
current balances as a Balances panel on the landing page, with a base-currency Total.

**Current behavior:**
`LandingController` (in `ledger`) renders `landing.html`: an eyebrow, the "Hello, %name%" / "Welcome"
greeting, a lede line, and — only before the base currency is set — a first-run panel pointing at
settings. Nothing else. The `account` table and the public `Account` record carry no "pin" concept.
The account editor (`account-edit.html`, backed by the `accounts` module's update path) edits name,
hue, paying-account detection labels, cash-account flag, and close-account.

**Desired behavior:**

*The flag*
- A new boolean account attribute, default `false`, meaning "show this account on the landing page".
  It is a column on `account`, written by the `accounts` module, and exposed on the public `Account`
  record so `ledger` can read it.
- The account editor gains a checkbox labelled **"Show on the main page"** wired through the existing
  account-update path. Persisting an edit round-trips the flag.
- The flag is only meaningful for `asset`/`liability` accounts (the only ones the editor edits).
  Person debt leaves, category-backing accounts, currency leaves and system accounts are out of
  scope — no UI exposes the flag for them.

*The Balances panel on the landing page*
- Shown only when the base currency is set AND at least one flagged account survives filtering.
  Otherwise render nothing — no empty panel, no placeholder, no discoverability hint.
- Lists each flagged account where `closed_at is null` and `deleted_at is null`, ordered
  alphabetically by account name. (The flag stays persisted for closed/deleted accounts; they are
  just filtered from the view.)
- Each row: a small colour tick from the account's stored `hue`, the account name (a link to the
  register filtered to that account — `/register?accountId=<id>`, plain full-page navigation), and
  the balance right-aligned.
- **Balance** = the sum of every live posting to the account (`transaction.deleted_at is null`),
  across the account's entire history, **with no date filter at all** (future-dated postings
  included). The opening-balance posting is included.
- **Currency display:**
  - Base-currency account: native balance only, formatted bare (e.g. `1.234,56`).
  - Non-base account: native balance with its symbol/ISO, followed by the base-currency equivalent
    in brackets, formatted bare (e.g. `10.000,00 CHF (9.200,00)`). The base equivalent is
    `native balance × rateAsOf(currency, today)` — mark-to-market at today's rate, consistent with
    the data-model balance-valuation rule (`native × rate@report-date`; report date is today even
    though the balance itself ignores posting dates).
- **Total row:** shown only when two or more accounts are pinned. A `Total` label and the sum of
  every row's base-currency value, formatted bare.
- **Missing rate:** if any pinned non-base account has no exchange rate (`rateAsOf` returns empty),
  that account still shows its native balance, its bracket shows `—` (or is omitted), and the
  **Total row is suppressed entirely** — never show a partial total as if whole (mirrors
  `PeopleOverviewService`'s "gloss is suppressed rather than shown partial" rule).
- Visual: a single minimal `.panel` headed **"Balances"**, consistent with the existing
  `.panel`/`.leaf-head` house style. No charts, no sparklines (FR-ANA-08).
- The panel sits below the greeting/lede. Issue `02`'s one-line stats sit above it; leave room for
  that line but do not build it here.

**Key interfaces:**
- `Account` (public record in `accounts`) — gains a boolean field for the flag. `AccountService` /
  the account-update command and `account-edit.html` handle reading and writing it.
- A new service in **`ledger`** (alongside `LandingController`), structured like
  `PeopleOverviewService`: takes the flagged accounts from the `accounts` read API, gets each
  balance from a repository method, values non-base balances via `ExchangeRateService.rateAsOf`,
  reads the base currency from `SettingsService`, and returns a render model (rows + optional total
  + whether the panel should render). It stays in `ledger` — it needs no `debts`/`receipts`, so no
  module move and no new dependency edge.
- A repository method returning the live-posting balance per account id for a set of account ids
  (or for all flagged accounts) — `sum(posting.amount)` grouped by account, joined to `transaction`
  for the `deleted_at is null` filter.
- `LandingController` — adds the Balances model attribute; unchanged routing, still in `ledger`.
- A Flyway migration adding the column (next free version, currently `V18`).

**Acceptance criteria:**
- [ ] The account editor shows a "Show on the main page" checkbox; toggling and saving round-trips
      the flag (integration test on the `accounts` update path).
- [ ] `./gradlew check` is fully green — all three suites, `ApplicationModules.verify()`, and every
      quality tool.
- [ ] `sqlLogicTest` covers the balance query: multi-currency accounts, a future-dated posting
      counted, the opening-balance posting counted, a soft-deleted transaction excluded, a
      closed account excluded, a deleted account excluded, an account with zero postings.
- [ ] Unit tests on the new `ledger` service: a missing rate suppresses the Total row, a
      base-currency account renders no bracket, rows are alphabetical, and an empty flagged set
      yields a "do not render" model.
- [ ] Integration test on `LandingController` via MockMvc: the panel renders rows + Total when
      ≥2 accounts are pinned; a single pinned account renders no Total row; rows link to
      `/register?accountId=`; the panel is absent when nothing is pinned; the panel is absent
      before the base currency is set.
- [ ] German number formatting via the shared formatting utility; base currency bare, non-base
      carries symbol/ISO. All copy English.
- [ ] `CONTEXT.md` "Pinned account" / "Balances panel" terms already added during triage — keep the
      implementation consistent with them.

**Out of scope:**
- Person debt balances on the landing page (the `/people` view owns those; may be revisited later).
- Categories, currency leaves, opening-balances or other system accounts as pinnable.
- A drag-to-reorder or sort-by-balance control (alphabetical only).
- A grand net-worth figure or anything beyond summing the pinned rows (that's FR-ANA-05, backlog).
- The tracking-stats line (issue `02`).
- Any caching of balances — compute on the fly; add a cache only if measured slow.
